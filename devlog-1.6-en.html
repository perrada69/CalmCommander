Calm Commander 1.6 — SCL archives and ZIP files

Version 1.6 adds a viewer for SCL archives and, for the first time, support for ZIP files — listed and extracted directly on the Spectrum, including compressed entries.

SCL archives

SCL files are now opened by the same plugin that handles TR-DOS disk images, and everything you already know from the TRD viewer works here as well.

  • An archive is recognised by the SINCLAIR signature at the start of the file rather than by its extension, so an SCL that arrived under some other name is still opened correctly.
  • The listing shows the name, type and length of every file, together with the number of sectors it occupies. An SCL carries no disk label, geometry or free space, so those columns are simply left out.
  • Extraction is identical to TRD: e writes out the entry under the cursor, Caps+e writes out all of them, and d switches the +3DOS header on and off.
  • Entries with a length of zero, which do occur in the wild, fall back to the sector count so that the file is still extracted whole.

ZIP files

Files with the .zip extension open in a new viewer that lists the contents of the archive and extracts them to the SD card. No external tool and no PC are needed at any point.

  • Every entry is listed with its original size, its packed size and a letter showing how it is stored: S for stored, D for deflate, X for encrypted, / for a folder and ? for a compression method Calm Commander does not implement.
  • The panel on the right shows the name the file will be given, its length and its type, so it is clear what will land on the card before anything is written.
  • e extracts the entry under the cursor, Caps+e extracts the whole archive.
  • Encrypted entries and unknown compression methods are listed but never extracted. ZIP64 archives are refused with a clear message.

How it works

A ZIP keeps its index at the very end of the file, which is awkward on a machine that can hold only a small part of a file in memory at once. The plugin therefore reads the index straight from the card at the position where it actually lies, and does the same for each file it later extracts.

Compressed entries are decompressed on the Spectrum by a full deflate decoder. Output is produced through a 32K window in extra memory, which doubles as the window deflate itself needs for its back references, and is handed over to the card in 8K pieces as it fills. Nothing is ever held in memory in one piece, so the size of an extracted file is not limited — a 640K disk image packed inside an archive is extracted just as reliably as a small screen.

Every extracted file is checked against the CRC32 recorded in the archive, so a damaged download is reported instead of quietly producing a broken file. Unpacking a large file takes a while on a Spectrum, so the plugin shows a running count of the bytes written and of the compressed data still to be read; BREAK stops an export that is taking longer than you are willing to wait.

Folders inside archives

One limitation is worth knowing about before you start, because it is a deliberate decision rather than an oversight: the folder structure of an archive is not recreated.

  • Every extracted file is created directly in the directory shown in the active panel. The path inside the archive is dropped and only the file name itself is used, shortened to the 8.3 form the card requires. An entry called demos/1997/screen.scr therefore lands in the current directory as SCREEN.SCR.
  • Folder entries in the archive are shown in the listing, marked with /, but they are skipped when extracting — no directories are created.
  • Two files with the same name in different folders will therefore overwrite each other during Caps+e. If an archive is built that way, extract those entries one at a time with e into directories of your choosing.

Recreating the tree is something I would like to add later; for now, unpacking into the current directory covers what these archives are usually used for on the Spectrum — a handful of demos, screens or disk images that you want on the card and nothing more.
