Calm Commander 1.7 — the mouse everywhere, older settings files and the 1MB Next

Version 1.7 brings no new viewer, but it makes Calm Commander more comfortable and more reliable: the mouse now works in every dialog and plugin, old settings files no longer break the controls, and the program should now run on a Next with 1 MB of memory as well. Everything applies both to the classic version started from cc.bas and to the .cc dot command.

The mouse in every dialog

Until now K-Mouse worked mainly in the panels and in the menu, and most dialogs knew nothing about it. The same rules now apply everywhere Calm Commander waits for a key — in confirmation dialogs, Help, bookmarks, Settings, the viewers and the editor:

  • The right button acts as BREAK — it closes a window and cancels a dialog or the menu.
  • The wheel acts as the up and down arrows, so it scrolls Help, the bookmark list or the file you are viewing.
  • Clicking a key hint printed on the screen is the same as pressing that key: ENTER = yes, BREAK = no, e:export, H=hex, EXT+S save in the editor, [ ENTER close ] or Press any key. You can click anywhere on the hint, the word yes for example.
  • The bottom line of the main screen is now clickable — clicking 5: COPY, 8: DELETE or 0: MENU runs that function.

In the panels everything stays as you know it: a click selects a file, a double click runs it, the right button marks it and the wheel scrolls the list. In the viewers, hints are looked for only in the top and bottom lines, so clicking into the displayed text never triggers anything, even if it happens to contain h=hex.

Because the hint is read straight from the screen, every dialog that prints its keys works with the mouse, including the ones still to come. The mouse is switched on as before with USE K-MOUSE in the Utils menu.

An older settings file no longer breaks the controls

If you used Calm Commander 1.3 or older and then moved to 1.5, 1.6 or the dot command, you may have found the controls scrambled after the first start: the arrow keys did something else, ENTER added a bookmark, the 5 key quit the program and the mouse in the panels could stop responding, for example. The colours could look odd as well.

The culprit was the conversion of C:/SYS/cc.cfg. Version 1.4 added colours and keys to the settings, and the conversion from an older settings file always assumed the 1.4 format. A file from an older version, which holds no colours or keys at all, was therefore converted into nonsense, and the result was saved, so the problem stayed on every later start.

  • Version 1.7 recognises which version the file comes from. From a file written by 0.6 to 1.3 it keeps the panel directories, cursor positions, the TAP machine choice, K-Mouse, the directory order and sorting, and sets the colours and keys to their defaults.
  • Files from 1.4 are converted as before, including your keys and colours.
  • The keys are now checked at start-up. If an action has no key, has BREAK, or two actions share a key, the default keys and colours come back. A file that was already broken earlier is therefore repaired automatically — the panel directories in it are kept.
  • Options outside their valid range (the TAP machine, the sort mode, the switches) go back to their default. An out-of-range machine choice in particular could previously write to memory it had no business touching.

One caveat: do not alternate version 1.4 with newer versions on the same cc.cfg. Version 1.4 does not know the new settings and overwrites them in its own way; 1.7 then notices and restores the default colours and keys, so your own settings are lost. Versions 0.6 to 1.3 do no harm to the settings of newer versions.

Calm Commander on the 1MB Next

A Next with 1 MB gives programs 768 KB of extended memory. Calm Commander used to keep several working buffers above that limit, in memory that only the 2MB Next has. On a 1MB machine basic file handling looked normal, but copying, moving and deleting directories, Dir info, bookmarks, Settings, the ZIP viewer, NXI and SCR pictures, part of any file longer than 56 KB in the viewer and the .copy, .del and .dirinfo dot commands all wrote to memory that is not there.

  • All the memory Calm Commander uses at fixed places is now within the first 768 KB.
  • The highest memory pages are left free. NextZXOS hands out memory to drivers and programs from the top down, so even on a 1MB machine .cc is unlikely to run into them.
  • If a page it needs is missing from the machine, .cc refuses to start with Not enough memory instead of writing into nothing.
  • The NXI and SCR viewers now draw into Layer 2 in memory that, according to the NextZXOS documentation, Layer 2 can display on every Next. They used to sit high in memory, where that may not hold even on a 2MB machine.

To be honest: I have not tried it on a real 1MB Next yet, and CSpect has no 1 MB mode. This has been checked by going through the code and by the automated tests, which now run on an emulated 1MB Next and fail whenever anything touches memory outside it. If you have a 1MB Next, I would love to hear whether everything works.

One more fix

  • In a directory with more than 420 entries, the long file names of the right panel could overflow into the file lists of both panels and into the saved screen. Each panel now has room for all 597 entries Calm Commander reads from a directory.
