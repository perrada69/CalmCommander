Calm Commander as a dot command — just type .cc

Calm Commander can now be started as a dot command. Type .cc at the NextBASIC prompt, look after your files, and press Quit — you are back in BASIC exactly where you left off, with your program, your variables and your screen untouched. No loader, no reset.

The classic version started from cc.bas stays as it is. Both versions share the same configuration and bookmarks, so you can use whichever suits you.

Installation

The download contains a build_dot folder laid out exactly like the SD card, so you only need to copy its contents to the root of C::

  • dot/cc goes to C:/DOT/ — that is the whole program in a single file.
  • sys/cc/*.ccp go to C:/SYS/CC/ — the viewer and tool plugins.

The configuration (cc.cfg) and the bookmarks (bookmark.cfg) stay in C:/SYS/ as before and are created automatically on the first start. .cc -h prints a short help.

Back to BASIC with everything intact

Calm Commander needs the whole of the Spectrum's main memory for itself, which is why the classic version can only end with a reset. The dot command solves this differently:

  • Before it starts, it copies all of BASIC's memory — the screen, the system variables, your program and its variables — into free extended memory, and puts it back when you quit.
  • The display settings (layers, tilemap, palette selection, transparency) and the CPU speed are restored as well, so you return to the same mode you left.
  • All memory borrowed for this is returned to NextZXOS, so nothing is lost until the next reset.

Calm Commander reserves the extended memory it uses through the NextZXOS memory manager, so it never overwrites memory that belongs to someone else. If another program or driver already holds a part of it, .cc refuses to start with Page NNN in use instead of risking a crash.

Starting programs

NEX, BAS, TAP, SNA, Z80 and SNX files are started straight from the file list, just as in the classic version.

  • A dot command cannot start a BASIC program by itself. Calm Commander therefore first puts BASIC back in order and then adds the start command to the line you typed — for example .cc becomes .cc:LOAD "game.bas". BASIC then carries on with the rest of the line and the program starts in your own, genuine BASIC environment, as if you had typed the command yourself.
  • This also works when .cc is called from a program, for example from line 10 .cc in an autoexec. The start command is then added to that program line in memory; the program being started replaces your program anyway.
  • For TAP files you choose the machine — 128k, 48k, Pentagon or Next — in the same dialog as in the classic version, and the timing is set accordingly.
  • Tapes and snapshots start at 3.5 MHz, BASIC programs at the speed you had set.

Fixes in the music players

While working on the dot command I found two problems in the music plugins, and the fixes apply to the classic version too:

  • The PT2, STC, STP and SQT players kept interrupts enabled while the song was mapped over the system variables, so the ROM interrupt routine could write into the song data. Song data is now mapped only with interrupts disabled.
  • ENTER (stop) and SPACE (next song) are now read directly from the keyboard in all players, so they react reliably.
  • The machine selection for TAP files shows Pentagon in full again.

Good to know

  • Calm Commander uses sprites for the mouse pointer, so sprites defined by your own program are cleared after you return to BASIC.
  • If a program started from a line like 10 .cc fails to load, the added start command stays in that line until you load another program.
  • The dot command needs NextZXOS; in 48K mode it reports Requires NextZXOS.
